# Submission text (draft for the owner to paste; sources: CLAIMS_TO_EVIDENCE.md, SHOWCASE_CHQCLR.md, MEASUREMENT.md)

**Name:** Diocle. **Track:** Indie, Build for Your World. **Video:** the link in the README's first line. **Repo:** https://github.com/Nivetha200111/Diocle. **Live:** https://diocle.vercel.app

**One line.** AI can rewrite COBOL in minutes; Diocle tests whether the Java still gives the same answer on the inputs it tries under GnuCOBOL, by comparing it with the original, attacking what passes, repairing what differs, and leaving evidence anyone can re-run.

**The problem.** I worked on a COBOL modernization at a global finance company where every translated program was checked by hand. AI can now write the Java in minutes. The bottleneck is deciding whether to accept it: a modernization lead or systems integrator needs to know whether the Java does what the batch program did, on more than the inputs someone thought of. A failed migration is expensive: TSB's 2018 migration cost the bank £330 million and brought a £48.65 million fine (https://www.itpro.com/business-strategy/it-infrastructure/369753/tsb-bank-fined-48-million-over-botched-it-upgrade). The people who benefit are the teams at banks, credit unions and payment operators who inherit these programs, and the people those programs pay.

**What it does.** Muse Spark translates. GnuCOBOL runs the original and a JVM runs the Java on the same generated records, and every output byte, display line and exit code must match. Java that passes is then attacked: Muse Spark designs inputs aimed at where it might differ, each run through both programs. A repair agent with tools fixes observed mismatches and is re-checked on records it never saw. No model certifies; the comparison does. Delivery is a pull request with an equivalence report and CI that re-runs the comparison on fresh inputs.

**One delivery to check.** quillmark-modern#4 (https://github.com/Nivetha200111/quillmark-modern/pull/4): six synthetic programs translated by Muse Spark for about $0.13 of estimated model spend, delivered as a pull request whose own CI re-ran the comparison on fresh generated inputs: 6,719 output records, 0 differences (https://github.com/Nivetha200111/quillmark-modern/actions/runs/40811476870).

**The finding.** On 15 synthetic programs with one model, 4 of the 10 attackable translations that passed a held-out check of 1,000 generated records then differed from the original on inputs Muse Spark designed: by the breaker's stated reasons, one on malformed numeric fields and three on a negative-zero sign byte at an overflow boundary. For example, on a returned cheque with a space in its numeric fee, the COBOL on GnuCOBOL charged 20.00 and the Java 0.00. That is byte-level disagreement under GnuCOBOL, not a claim about IBM's compiler, and no stored break shows a wrong amount on a well-formed record. Auditing our own evidence, we found two flaws and published them: our generator gave that showcased program near-identical records, and the attack compared output records but not printed totals, so it missed a wrong total in one stored private-mode Java. The first is fixed for that record shape and the second is fixed; flat text records remain a stated limit. We re-measured with both fixed, under a plan written first: 4 of 10 again, the same four programs. It is not a defect-detection rate.

**On code we did not write.** Every program in the Open Mainframe Project's public COBOL course, at a pinned commit, under protocols written before each run, in three dated passes for $2.07 of model spend. Of 32 programs, the first two passes certified 11: 9 as distributed but on fixed input, and 2 against a repaired copy with the patch published. Of the 13 not certified, 11 use WRITE ... AFTER ADVANCING. GnuCOBOL writes the advancing into the file as bytes, and our verifier refused even identical Java while our prompts had no rule for it. After fixing both, a third pass, not a blind test because the fix answered this same course's failures, certified 9 of those 13: 8 against a repaired copy and 1 as distributed on fixed input. That leaves 3 not certified and 1 whose original never ends, plus 3 that could not be patched to compile, 4 refused and 1 not converted. The earlier passes stand as recorded. No program was certified as distributed on inputs that vary, the repaired copies vary 2 of 10 input fields, and these are small teaching programs, so this does not show Diocle works on any repository (https://github.com/Nivetha200111/Diocle/blob/main/docs/EXTERNAL_ESTATE.md).

**A blind test.** On code no fix had seen, under a protocol pinned before the run, $0.29: the COBOL sources in the public repository of Norway's retired national pension system (navikt/DSF, MIT; its README says the system ran in production 1967 to 2018 and is written in PL/I; whether these programs ran in production is not established). 2 of the 4 Diocle could test certified with no patch to the COBOL, after the repair agent fixed the first Java, and 2 did not. They are small programs on generated inputs, varying 1 of 7 and 6 of 10 input fields, where the breaker could not run, and nobody at NAV was involved. Separately, fzn0x/core-banking-system certified 0 of 2 and ibmdbbdev/Samples only 11 very small programs. The repositories were chosen because the analyzer could test them, 7 of the 12 checked had nothing it could test, and blind means only that no fix or tuning was made for them (https://github.com/Nivetha200111/Diocle/blob/main/docs/BLIND_TEST.md).

**"Use of Meta products" form field (paste this).** Muse Spark through the Meta Model API is the default: it translates COBOL to Java, repairs observed mismatches as a tool-using agent, and attacks Java that passed by designing inputs (71, 33 and 29 of 83 public runs, Nov 3). A model never certifies; the GnuCOBOL comparison decides. Muse Spark Open runs on Fireworks and Baseten. Optional private mode moves the agents to it and is thinly tested: 11 public runs with no Muse Spark call, 6 reaching all three roles, 6 certified, too few to compare with Muse Spark. It also writes an optional guard review after a run certifies on the live engine, unless a dollar cap stops it first (finished in 38 of the 83; no public run shows it catching a real defect). With thinner evidence: Muse Wonder reads a printed COBOL listing (one listing so far), which is then compiled and compared with the original; Muse Voice Transcribe transcribes a spoken question, Muse Spark turns it into claims, and the answer uses only claims whose examples GnuCOBOL confirmed; Muse Code uses Diocle as a local plugin. Not every run uses every model. Bonus categories: Best Agentic Use-Case, and Best Build on Meta Open Weight Models (private mode on partner inference).

**Meta models, by role.** Muse Spark: translator in most public runs, tool-using repair agent in about 40% and breaker in about 35% (Nov 3: 71, 33 and 29 of 83). Also, with thinner evidence, stated per model in docs/META_MODELS.md: Muse Spark Open on partner hosts (private mode, optional cross-check and guard review), Muse Wonder (reading a printed listing, and once as breaker), Muse Voice Transcribe (a spoken question answered from what GnuCOBOL confirmed), and Muse Code (a local plugin). Not every run uses every model.

**Try it in three minutes.** Open the site and press Try the sample (re-checks stored Java on fresh records, no model). Open the CHQCLR run for the mismatch, the repair and the list of which checks ran. Or locally with no key: `sh scripts/quickstart.sh --no-key` (1,027 of 1,027 output records; a re-check of stored Java, not a new conversion).

**Limits.** Testing on stated inputs, not a formal proof. GnuCOBOL, not IBM Enterprise COBOL. SQLite and Berkeley DB stand in for the DB2 and VSAM subsets. The breaker attacks single-file record programs. Generated records carry no deliberately bad data, and a flat text record gets placeholders. Optional guard and cross-check steps can be skipped, and a run says so. Synthetic programs, small sample, one model in the measurement. On the public repository, none of the 11 programs using WRITE ... AFTER ADVANCING that reached a comparison certified. Model spend is about two cents median per certified run; compute, hosting and human review are not measured. No customers or pilots are claimed.
